# THIRD ADVERSARIAL PASS — the proposed amendment audits itself

Conducted 2026-09-03, before Amendments 3 and 4 and before any HAI detector
run. The subject of this audit is the **proposed P0c**, not the existing
preregistration. No registered claim is altered here.

**Headline: the proposed P0c was refuted by measurement before it was ever
registered.** The permutation formulation is invalid for this data. The
p-value-versus-percentile question the brief asked about is real but
second-order relative to that.

---

## 0. THE MEASUREMENT THAT KILLS THE PROPOSED P0c

Simulated: 20,000 ticks, attack labels in 12 contiguous blocks of 66 ticks,
prevalence 0.0396 — deliberately shaped like HAI. The "detector" is pure
noise with zero detection ability, in two flavours.

| Null detector | Permutation false-PASS at alpha 0.01 | Circular-shift false-PASS |
|---|---|---|
| iid noise, phi = 0 | 2/60 = 0.033 | 2/60 = 0.033 |
| smooth noise, phi = 0.999 | **18/60 = 0.300** | **0/60 = 0.000** |

A useless-but-smooth detector passes the proposed P0c thirty percent of the
time at a nominal one percent level.

**Why.** HAI attacks are contiguous blocks. Random permutation scatters them,
so the null distribution is generated from unstructured label vectors while
the observed statistic uses a structured one. The null is the wrong null, and
the test is anti-conservative for any autocorrelated score series.

**Why this is not an edge case.** A Jensen–Shannon divergence computed over a
sliding window is autocorrelated by construction — consecutive windows share
`W-1` of their samples. SENTINEL produces exactly the score shape that breaks
this test. The second audit's registered limitation described this as a
time-of-day detector concern. That understated it by a wide margin.

**The fix costs nothing.** Replace random permutation with **random circular
shift** of the label vector. A shift preserves the contiguous-block structure
exactly and destroys only the alignment between scores and labels, which is
the quantity under test. Block permutation was rejected in the second pass for
introducing a block-size parameter. A circular shift has no parameter at all.

Guard band: not required. With `N` = 153,000 and attacks spanning a few
thousand ticks, the probability that a uniform draw from `1..N-1` lands close
enough to zero to materially re-align labels is negligible. Adding a guard
band would reintroduce exactly the tunable parameter the shift avoids.

## 1. THE SIX VERIFICATION QUESTIONS

**1. Is the test valid for average precision?**
Yes, and the validity does not depend on AP at all. A permutation or shift
test is statistic-agnostic: under the null, the reference distribution is
generated by the resampling scheme, so any function of scores and labels is
admissible. AP needs no distributional assumption. **The validity question is
entirely about the resampling scheme, which is where it failed.**

**2. Is the +1 correction appropriate?**
Yes, and it is necessary rather than cosmetic. Without it the p-value can be
exactly 0, which no exact test may produce, and the resulting test is
anti-conservative. Including the observed statistic in its own reference set
gives `P(p <= alpha) <= alpha` under the null. Keep it.

**3. Does B = 200 give sufficient resolution at alpha = 0.01?**
Attainable but coarse. The smallest achievable p-value is `1/201 = 0.004975`,
so `p < 0.01` is reachable — but only two attainable values fall below the
threshold, `1/201` and `2/201 = 0.00995`. The decision therefore reduces to
"at most one of 200 null draws beat the observed value", which is a one-bit
decision resting on the extreme tail.

> **Recommend B = 999.** Smallest p-value `0.001`; `p < 0.01` corresponds to
> `k <= 8`, a far more stable decision. Cost is negligible: the scores are
> fixed across draws, so sorting once and taking an `O(n)` pass per draw makes
> 999 shifts cheaper than one naive re-sort per draw.

**4. Are ties handled deterministically?**
Two distinct tie problems, and only one is currently handled.

*Ties between null and observed:* the `>=` in the numerator is the
conservative, standard, deterministic choice. Correct as proposed.

*Ties among scores inside the AP computation:* **unhandled, and hazardous
here.** AP depends on rank order. If tied scores are broken by array index —
which is what a stable argsort does — then, because attack labels are
contiguous in index, the tie-breaking correlates with the labels and AP is
biased. JSD computed over a finite histogram will produce many exact ties.

This is the same defect class as note054, where a Spearman correlation
published at +0.117 was sort-path dependent and the tie-corrected value was
+0.1480. **Tie handling must be specified as grouped-rank AP, in which all
observations sharing a score value are treated as a single threshold group,
and must be verified to give identical output under at least two sort
algorithms before it is trusted.**

**5. Does the fixed seed create an inferential problem?**
No. The resampling draw is ancillary to the data, so conditioning on it does
not invalidate the test. The residual risk is seed-shopping by the author, and
it is closed by the seed being registered in a commit that precedes the run —
`20260903` already is. At `B = 999` the leverage of any single seed is small.

**6. Any hidden choice left in generating the resamples?**
Four, all closeable now:
- **RNG identity.** `np.random.default_rng(20260903)` uses PCG64; the legacy
  `np.random.RandomState` produces a different stream. The generator must be
  named in the registration, not implied.
- **Draw range.** Shifts drawn as `rng.integers(1, N)`, excluding 0.
- **Identity inclusion.** The unshifted vector is not one of the `B` draws; it
  enters only through the `+1`.
- **Cross-architecture determinism.** note054's error was found only by running
  on a second CPU architecture. The AP implementation must produce
  bit-identical output in the container and on the S25 before any result is
  claimed.

## 2. DOES P0c BELONG INSIDE P0?

**No. Combining calibration and discrimination under one PASS/VOID gate is
scientifically incoherent, and the current name makes readers apply the wrong
semantics.**

P0a and P0b test the **instrument**. If they fail, the measurements are
meaningless, so P1 and P3 are VOID — nothing was learned. That is the correct
consequence of an invalid instrument.

A discrimination test measures a property of **this detector**, not of the
instrument. If it fails, the instrument was working perfectly and validly
measured that the detector has no discriminative power. That is a **result**,
not a void.

Concretely: P3 asks whether conformal coverage falls below nominal. Coverage
is a calibration property and is perfectly well-defined for a detector with
zero discrimination. Voiding P3 because the detector cannot discriminate would
throw away a valid measurement of a different thing.

> **Recommendation: register it as P5, not P0c.** The `P0` prefix carries gate
> semantics that a future reader will apply mechanically. Its consequence is
> **annotation, not void**: if P5 fails, P1 and P3 are still computed and
> reported, and every reported number carries the annotation that
> discrimination was not established. A P5 failure is then the headline result
> rather than a suppressed one.

This also preserves the existing prereg's logic untouched — P0 keeps exactly
the two members it was registered with.

## 3. THE NULL DETECTOR — EXACT STATEMENT

Distinguishing the four things the brief asked to separate:

- **Expected coverage.** For split conformal with `n_cal` calibration scores
  and the order-statistic quantile `ceil((n_cal+1)(1-alpha))`, marginal
  coverage lies in `[1-alpha, 1-alpha + 1/(n_cal+1)]` **provided calibration
  and test scores are exchangeable**.
- **Realized finite-sample coverage.** A random quantity, not the nominal
  value. Conditional on the calibration set it is Beta-distributed; its
  standard deviation across test slices is approximately
  `sqrt(alpha(1-alpha)/n_test)`.
- **Exchangeability.** Holds *exactly* for the `U(0,1)` null detector, because
  its scores are iid by construction and independent of the input. It does
  **not** hold for a real detector on HAI — P3 predicts precisely that it
  fails.
- **Quantile convention.** The order-statistic and empirical-quantile
  conventions differ by `O(1/n_cal)`. Negligible at `n_cal` on the order of
  10^5, but it must be named, not assumed.

> **Text safe for the preregistration:** A detector whose scores are iid
> `U(0,1)` and independent of the input satisfies split conformal's
> exchangeability assumption exactly. Its marginal breach rate therefore lies
> in `[alpha, alpha + 1/(n_cal+1)]`, and its realized breach rate on a finite
> clean slice is a random quantity with standard deviation approximately
> `sqrt(alpha(1-alpha)/n_test)`. For the sample sizes here it satisfies P0a's
> interval with probability close to one. **This establishes only that P0a
> cannot exclude a detector with zero discriminative power.** It establishes
> nothing about real detectors, whose exchangeability is not guaranteed.

Overstatements deliberately avoided: it is *not* claimed that the null
detector passes P0a with probability one, nor that its coverage equals
nominal exactly, nor that real detectors inherit the guarantee.

Only the two git-based gates survive. Every other artifact is a file the
author writes, asserting that something happened.

**Uniform redesign.** Every gate's artifact becomes a **GitHub Actions job
running from a clean checkout**, whose pass/fail an observer reads from
GitHub's own run record rather than from a file in the repository. Actions is
free and unlimited on public repositories, so there is no cost argument
against it.

**`FROZEN.md` is replaced by `frozen.py`.** Constants must live in one module
that the detector *imports*, so a value cannot be frozen in prose and
different in code. The gate then becomes mechanically checkable in three
parts: the constants exist in `frozen.py`; a CI test asserts their values; and
`git merge-base --is-ancestor <freeze-commit> <result-commit>` proves the
freeze preceded the run. All three are observable without trusting anyone.

**G13 remains the irrecoverable one.** Every other gate can be satisfied late.
G13 can only be preserved.

## 5. WHAT CHANGED IN THIS PASS

- The proposed P0c permutation test is **withdrawn before registration**,
  refuted by measurement at a 30% false-pass rate against a useless detector.
- Replaced by a **circular-shift** test, which adds no parameter and measured
  0 of 60 false passes on the same null.
- Exact p-value adopted: `p = (1 + #{AP_b >= AP_true}) / (B+1)`, `B = 999`,
  `alpha = 0.01`.
- Tie handling inside AP identified as an unaddressed note054-class hazard.
- Renamed **P5**, with annotation semantics rather than VOID, because
  discrimination is a property of the detector and not of the instrument.
- Eleven of thirteen gate artifacts redesigned from author-written files to CI
  jobs.

No existing registered claim was altered by this document.
